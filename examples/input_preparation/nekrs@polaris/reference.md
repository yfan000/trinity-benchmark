1. `pipe.par` — NekRS parameter file controlling polynomial order, timestep count, solver tolerances, and statistics collection window.

Minimum correct contents must include:
- `[GENERAL]` section with `polynomialOrder = 7`, `numSteps = 20000`, a valid `dt`, and `timeStepper` (e.g. `tombo2`)
- Statistics collection starting at step 10000 (final 10,000 of 20,000 steps), expressed via `startFrom` or a stats-start field if supported, or via UDF logic — the `.par` must at minimum declare `numSteps = 20000`

- `[PRESSURE]` section with `residualTol`
- `boundaryTypeMap` entries appropriate for a pipe: wall (no-slip) and periodic inlet/outlet

2. `pipe.udf` — C++ user-defined function file implementing at minimum `UDF_Setup()` and optionally `UDF_ExecuteStep()` for statistics accumulation over the final 10,000 steps.

Binary / runtime-generated files (NOT hand-written):
- `pipe.re2` — binary mesh file for the pipe with 32,000 spectral elements; generated by running a mesh tool such as:
  `gmsh2nek` or `exo2nek` on a suitable cylindrical mesh, or
  `nekrs --setup pipe` with a pre-existing Nek5000 `.rea`/`.re2` workflow.
  Example command: `$NEKRS_HOME/bin/nekrs --setup pipe --build-only` after placing a valid `.re2` produced by the appropriate mesh converter.

- `.oudf` — GPU kernel overrides (not needed unless custom forcing or boundary kernels are required)
- `.usr` — legacy Nek5000 Fortran hooks (not needed for a pure NekRS run)
